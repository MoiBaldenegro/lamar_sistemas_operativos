02 · Introducción

¿Qué hace realmente un Sistema Operativo?

No produce nada por sí mismo: es un intermediario y un asignador de recursos entre programas que compiten.

El gran árbitro

Cuando dos programas quieren la CPU, la RAM o el disco al mismo tiempo, alguien debe decidir. Ese alguien es el SO.

Doble misión

Ofrecer una máquina cómoda y segura al programador, y a la vez exprimir al máximo el hardware disponible.

Objetivo de hoy

Entender las funciones (lo que el SO promete) y las operaciones (los mecanismos técnicos que usa para cumplirlo).

La analogía del restaurante flujo en vivo

Clientes

Los programas piden CPU, memoria y disco.

Gerente (SO)

Decide a quién se le sirve primero y cuánto.

Cocina

El hardware ejecuta el trabajo real.

Sin gerente: caos, clientes que se pisan y comida que nunca llega. Con SO: orden, turnos y reglas claras.

03 · Funciones

Las 4 funciones principales

El núcleo de sus responsabilidades. Toca cada tarjeta para ver el mecanismo que hay debajo.

01 Gestión de procesos Decide qué programa usa la CPU, cuándo y por cuánto tiempo.

Mantiene el estado de cada proceso (listo, ejecutando, bloqueado), aplica políticas de planificación y realiza cambios de contexto para repartir la CPU con equidad.

SchedulingPCBContext switch
02 Administración de memoria Reparte la RAM para que los programas no choquen entre sí.

Cada proceso recibe su propio espacio aislado. La memoria virtual y la paginación permiten usar más memoria de la que físicamente existe, sin que los programas lo noten.

03 Almacenamiento y archivos Controla cómo se guardan, leen y organizan los datos.

El sistema de archivos convierte bits crudos del disco en carpetas, archivos y metadatos. Añade journaling para resistir cortes de energía y permisos para proteger la información.

04 Abstracción del hardware (E/S) El programador no necesita saber cómo funciona electrónicamente un ratón o una pantalla.

Los controladores (drivers) esconden la complejidad de cada dispositivo tras una interfaz uniforme: abrir, leer, escribir, cerrar. Las interrupciones avisan al SO cuando algo terminó.

04 · Operación clave 1

Las llamadas al sistema

El puente entre el usuario y el hardware: la única interfaz legítima para pedirle favores al núcleo.

El cambio de modo

El programa vive en modo usuario (restringido). Para tocar hardware debe cruzar una puerta segura y entrar en modo kernel (privilegio total). Al terminar, vuelve a modo usuario.

  • fork() · crear un nuevo proceso
  • read() / write() · leer o escribir en un archivo
  • chmod() · cambiar permisos de un archivo
!

No puedes saltarte la puerta: el hardware lo impide mediante anillos de protección. Un acceso ilegal termina en una excepción, no en acceso concedido.

06 · Operación clave 3

Memoria virtual: mucho con muy poco

El truco de magia: hacerle creer a los programas que tienen RAM infinita usando espacio del disco.

Páginas y marcos

La memoria se divide en trozos fijos llamados páginas. La RAM se divide en marcos del mismo tamaño. El SO traduce direcciones virtuales a direcciones físicas.

Fallo de página

El programa pide un dato que está en el disco y no en la RAM. El SO detiene el proceso, trae la página, actualiza la tabla y continúa. Si no hay marcos libres, expulsa una página (FIFO o LRU).

08 · Conclusiones

El SO: el héroe invisible

Sin sus funciones y operaciones, programar sería hablar directamente con los electrones.

Abstracción perfecta

Una API uniforme esconde miles de detalles del hardware. Escribimos read(), no instrucciones de disco.

Eficiencia y equidad

Maximiza el uso del hardware sin que ningún proceso muera de hambre (starvation).

Seguridad y aislamiento

Cada proceso vive en su burbuja. Los permisos y los anillos de protección evitan que uno dañe a los demás.
